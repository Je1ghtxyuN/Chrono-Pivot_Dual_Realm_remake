# 关卡路线与 Demo 脚本

工程：`D:/_work/_SRTP/ChronoPivot_ReportVR`。平台：Windows x64，SteamVR OpenXR。

## 空间修正

- 15 个场景都有连续游览路线、三个顺序节点和完成出口。
- 园林：石桥桥头与两岸重叠衔接；月门两侧接坡；步道连接水工装置、桥梁和月门。
- 观星台：原台阶在平台前仍有明显高差，改为连续缓坡与落地平台，补齐侧边护栏。
- 电磁实验室：拆分后墙，门洞宽 2.4m；玻璃门有独立碰撞与滑动部件。
- 实验室：入口缓冲、设备观察位、绕行通道、实际后门洞、出口落地平台及顶面。
- 频率耦合：路线从机械区绕过隔墙后端进入电磁区，避免穿过摆架、桌面和隔墙。
- 工坊：绕开网格实验平台和零件架，移动挡路盆栽；新增多米诺各自的运动轴。
- 冰雪：两座独立自建木桥连接两岸；桥头缓坡连接地面；投掷位置与补给区分开。
- 展厅：缩小展台边沿，保留中轴和两侧观察空间。
- 光线、轨迹、声波、荷叶等示意几何移除阻挡碰撞，实际支架和设备保留碰撞。

## 试玩

左摇杆行走，右摇杆分段转向。读取当前节点的目标和线索，先点选 A/B/C 或抓取物件放入同名槽位，松手后再按“验证”。正确物件松手进入槽位后会固定，可再次抓起；“提示”按钮提供解法引导。右握把、桌面左键/E都可操作面板，按住可抓物件。左菜单键、左次按钮或 R 重置。三步完成后等待门完全打开，沿步道走入出口进入下一关。

未通关时扳机、PageUp/PageDown和场景列表不能跳关。编辑器调试可勾选 `ReportSceneBrowser.allowDebugNavigation`。详细答案见 [逐关解谜攻略](逐关解谜攻略.md)。

中文标牌在 Windows 上使用系统的 Microsoft YaHei/SimHei 字体，字体文件没有打包到工程。

## 脚本结构

- `DemoLevel`：验证交互顺序、推进目标、更新任务牌、开启门锁、恢复出生位置。
- `DemoStation`：参数预设与演示动作，保存初始姿态以支持重置。
- `ReportPuzzle`：主动选项、归位与额外配重检查，给出目标、线索、提示和错误反馈。
- `ReportPuzzleButton`：选项或提示按钮；选择后仍需验证。
- `ReportPlacementSocket`：松手后吸附固定正确物件，再抓取时解除固定。
- `DemoPhysics`：简化浮力比例、频率匹配、单摆频率和理想螺线管磁场公式，使用 SI 单位。
- `DemoInteractor`：OpenXR/Input System 动作绑定、4m 射线、握把按下触发和中文字体。
- `DemoExit`：任务完成且玩家进入出口后切换下一关。
- `PolishReportLevels`：自建网格、动件拆分、门洞、路径、控制台；所有新增模型位于 `Assets/ReportVR/LevelModels`。

## 实现范围

这些是基础交互演示和后续开发起点。船体升降、共振振幅、光路显示、泄漏修复、雪球轨迹与多米诺使用简化公式或预设动画；没有完整流体、声学、电路或刚体连锁求解。声学高频振动以慢速动画表现，避免显示采样混叠。双区耦合目前由单个玩家顺序操作，没有网络同步或双人玩法。热学与展览关卡依据线索完成主动选择检验。

扩展功能时可在 `DemoStation.Activate()` 对应分支接入真实实验组件，并通过 `DemoLevel.Use()` 的成功结果推进目标。不要直接以物体点击次数代替实验条件。

## 验证与恢复

- `DemoTests()` 检查过载浮力、调频容差、单摆频率及顺序推进/重复操作/重置。
- `PolishReportLevels.Validate()` 每0.18m检查地面、坡度、高差和0.46m胶囊净空，再用实际 CharacterController 行走整条路线。电磁门以完成后的开启状态检查。
- `OfflineVRCheck` 在 Play Mode 中使用模拟头显和手柄，测试射线交互、全部节点完成、模型姿态与门锁重置、行走、转向、切换及首尾循环。
- `LevelReview/Before` 与 `After` 为改造前后照片，`SceneBackups` 是原场景快照。重新生成布局会恢复这些快照；手动编辑后应先另存副本。
- 物理头显的双眼显示、SteamVR 串流、按钮映射和舒适度仍需连接设备实测。
