# 本机 3B 物理导师（NF4 四位量化）

基础模型为 `models/Qwen2.5-3B-Instruct`，物理 LoRA 为 `outputs/run_001/best_adapter`。基础权重和适配器均保留原始文件；运行时将基础模型加载为 NF4 四位量化，并启用双重量化。计算精度由 CUDA 能力选择 BF16 或 FP16，LoRA 不强制量化。

## 启动与文字输入

双击本目录的 `启动导师.cmd`。首次加载可能较慢，看到 `READY http://127.0.0.1:18080/api/tutor` 后再发送问题。关闭该窗口或按 Ctrl+C 会停止服务并释放模型资源。

Unity 使用实验手册中的「AI 物理导师」页面，问题框支持文字输入。服务地址为 `http://127.0.0.1:18080/api/tutor`。模型路径本身不会启动服务，必须先运行启动脚本。此服务仅监听本机回环地址。

- `prototype_delivery/local_backend.py`：实际 CUDA NF4 基础模型和 PEFT 适配器加载。
- `prototype_delivery/local_server.py`：本机 HTTP 服务，复用原请求契约、知识卡检索和教学核验。
- `prototype_delivery/config.json`：基础模型路径、适配器路径和生成上限。
- `prototype_delivery/results/local_4bit_*/requests.jsonl`：问题、原始模型输出、公开响应、耗时和资源数据。
- `prototype_delivery/tests/local_text_check.py`：真实 HTTP 文字测试，需要服务已启动。

单次输入上限为 4096 token，单次生成最多 512 token，单卡逐个处理请求；过长输入会要求缩短问题或开启新对话，忙碌时返回 429。服务失败不会生成替代回答。文本教学仍需人工判断物理正确性，格式与引用核验不能代替专家审核。

## 独立环境与重装

已使用本目录 `.venv`，不修改系统 Python。需要重建时，在本目录执行：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124
.venv\Scripts\python.exe -m pip install -r prototype_delivery\requirements-service.txt
.venv\Scripts\python.exe -X utf8 prototype_delivery\local_server.py --config prototype_delivery\config.json
```

CUDA 驱动需支持上述 PyTorch 运行时。模型与分词器从本地文件加载，不上传问题；安装依赖需要网络。

## 保留的旧检查代码

`load_trained_adapter.py` 仍是原 Slurm 加载检查脚本，依赖本包未包含的 `data/test.jsonl`；本机运行请使用 `local_server.py`。`e2e_check.py` 仍需预备请求记录。模型权重放在 Unity Assets 以外，插件包不包含基础模型、适配器或 Python 环境。
